# 苏打阅读公网发布与手机 App 路线

> 核对日期：2026-07-26。本清单是工程与产品上线准备，不替代律师、备案服务商或应用商店的正式审核意见。

## 当前结论

现有项目适合继续做内测，不适合直接暴露到公网。网页/PWA、阅读器、本地导入、内容管道和
免费翻译路由已经可运行；生产登录、持久化账号、管理后台身份体系、隐私与备案材料仍需补齐。

推荐分三步上线：

1. **7 天影子运行**：不自动发布文章，人工检查来源、事实、难度和翻译失败。
2. **受邀 Web Beta**：完成真实短信、PostgreSQL、HTTPS、管理员鉴权和删除账号后，小范围开放。
3. **原生 App**：在 Web Beta 稳定后，用 Expo/React Native 做 iOS 与 Android，共享业务逻辑，
   不把当前网页简单塞进长期使用的 WebView 壳。

## 翻译速度、准确率与费用

### 分层路由

每次点词不应直接等一个大模型：

1. 浏览器内存缓存：当前阅读会话再次点击立即返回。
2. 后端内存与 Redis 缓存：相同正文哈希、词、句子、上下文、提示词版本和模型版本复用结果。
3. 免费上下文模型：智谱、ModelScope、硅基流动按质量、近期成功率和延迟动态排序。
4. 腾讯机器翻译：仅在控制台关闭后付费并显式开启保护标记后，使用每月循环免费字符包做
   `basic` 基础翻译。
5. 付费模型：默认永不自动调用；只能在有每日预算、单次上限且用户明确选择“精确翻译”时使用。

不要默认“同时请求两个模型，谁快用谁”。它会把调用量和潜在费用接近翻倍。更好的策略是短时
熔断拥堵模型、合并相同并发请求、缓存公共文章的热门词句，并只在高价值请求上升级模型。

### 性价比计算

按量服务应统一换算成“每个完成阅读用户的翻译成本”，而不是只看每百万 Token 单价：

```text
单用户成本 =
（未命中缓存的上下文字符或 Token × 单价）
÷ 完成文章的用户数
```

公共推荐文章的上下文完全一致，缓存收益很高；用户私有导入内容的重复率低，应该设置更严格的
每日点词/句译软额度。后台至少监控：

- 缓存命中率、每篇文章唯一翻译请求数。
- 每位日活用户的点词数、句译数和失败重试数。
- 各供应商成功率、429、超时、P50/P95 延迟。
- 免费额度剩余量、预估当日费用和预算拒绝次数。
- 人工准确率：多义词、代词指代、专名、论文术语分别统计。

只有当某供应商在 300 条人工校对集上达到平均 4/5，且线上 P95 和错误率合格，才能进入自动路由。

## 内容质量深化

采集数量不是目标，最终应优化“可读、可信、能学到”的比例：

- 标题和证据摘要都必须是英文；摘要不足以支持事实时不进入成稿。
- 论文区分同行评审与预印本；健康、治疗、因果和争议内容必须人工审核。
- 首页明确显示来源日期、CEFR、预计时长、推荐理由和“来源原文 / 苏打导读”身份。
- 用户读完后只收集轻量反馈：太难、合适、太简单、不感兴趣。
- 用真实查词密度回调难度：每 100 词 3–7 次为目标区间。
- 每周人工抽检自动文章；任意数字、日期、结论都能点回证据。
- 备用池不能把旧文章伪装成“今天发布”，应明确显示“备用导读”。

自动发布继续保持关闭，直到连续 7 天满足：无非英文标题、无未授权全文、事实可追溯率 100%、
人工评分平均至少 4.3/5。

## 公网发布前的工程门槛

### P0：不完成就不能公网开放

- 接入真实短信供应商；删除开发验证码和网络失败时的演示登录。
- 账号与会话落到 PostgreSQL；使用短时 Access Token、可轮换 Refresh Token、设备退出和令牌吊销。
- 管理后台使用独立管理员登录、MFA、操作审计；禁止匿名访问 `/admin/*`。
- 域名、HTTPS、HSTS、严格 CORS、反向代理、WAF、接口限流和短信防刷。
- 密钥放云密钥管理服务，不写镜像、日志、前端构建或 Git。
- PostgreSQL 自动备份与恢复演练；Redis、Worker、Beat 只运行受控实例。
- 错误监控、慢请求、模型余额、采集失败、午夜发布失败告警。
- 隐私政策、用户协议、儿童/未成年人条款、第三方 SDK 清单、个人信息清单、权限清单。
- App 内提供账号注销、数据导出/删除入口；网页提供同等删除申请入口。
- 首次云翻译前说明“当前词句和必要相邻上下文会发送给模型供应商”，导入原文件不上传。

项目现在已在生产模式下关闭演示短信，并要求管理接口 Token；这只是“失败时安全”，真实短信和
完整管理员账号体系仍需实现。

### P1：公开测试前完成

- PostgreSQL + Alembic 正式迁移；为推荐、进度、生词和额度建立索引及保留策略。
- API 幂等、请求 ID、结构化日志和个人信息脱敏。
- 翻译 Redis 缓存启用，做单实例和多实例压测。
- 灰度发布、健康检查、滚动回退和静态资源版本化。
- 低端 Android、iPhone 小屏、大字体、读屏、弱网和断网测试。
- 内容版权台账、下架入口、投诉邮箱和 24 小时问题内容停用流程。

## 中国大陆公网与 App 备案

网站和 App 都属于互联网信息服务。工信部说明，APP 主办者由网络接入服务提供者或应用分发平台
通过备案系统在线提交材料；网站通常先完成域名实名、境内服务器接入和 ICP 备案：

- [工信部 APP 备案通知解读](https://wap.miit.gov.cn/jgsj/xgj/hlwgl/art/2023/art_564bf0759d7e41d5b4aa8ce4996b9e84.html)
- [互联网信息服务备案服务指南](https://hunca.miit.gov.cn/bsfw/bszn/art/2024/art_7ef0d8bd3b0d433ba4b9b277f883f74d.html)

建议按以下顺序准备：

1. 确定主办主体、域名、境内云厂商与服务器。
2. 完成域名实名和网站 ICP 备案，再部署正式 API 与隐私页面。
3. 取得 iOS Bundle ID、Android 包名、签名证书与公钥指纹。
4. 通过云厂商或分发平台提交 APP 备案，备案信息与应用商店主体保持一致。
5. 在网页页脚和 App 显著位置展示备案号。

苏打阅读会向境内公众提供模型翻译和系统原创学习导读，属于应重点复核的生成式 AI 应用场景。
《生成式人工智能服务管理暂行办法》适用于向境内公众提供生成内容的服务。上线前应让合规律师和
模型供应商确认：使用已备案第三方模型时本产品需要承担的安全评估、算法/服务备案、生成内容标识、
投诉处置和日志义务。

- [国家网信办《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)

## 手机 App 技术路线

### 推荐架构

建立 Expo/React Native 应用，并抽出可共享包：

```text
apps/web          当前 React/Vite PWA
apps/mobile       Expo Router / React Native
packages/core     类型、分词、句切分、推荐规则、API 客户端
packages/storage  Web IndexedDB 与 Native SQLite 的统一接口
```

移动端使用：

- `expo-document-picker`：选择 EPUB、TXT、PDF。
- `expo-file-system`：把导入文件保存在应用沙盒。
- `expo-sqlite`：章节索引、内容哈希、阅读进度、生词和本地缓存。
- `expo-secure-store`：Refresh Token。
- `expo-notifications`：每日提醒和深链到主推荐。
- 虚拟列表/分章渲染：避免整本书一次性挂载导致卡顿。

React Native 官方支持用平台专用文件保留 Web/Native 差异，同时共享通用代码：
[React Native 平台专用代码](https://reactnative.dev/docs/platform-specific-code)。
商店构建可使用 Expo EAS：
[Expo EAS Build](https://docs.expo.dev/build/setup/)。

### 迁移顺序

1. 抽出 `packages/core`，让 Web 测试继续通过。
2. 实现登录、首页和推荐文章阅读。
3. 实现词下翻译、句下翻译、生词和进度。
4. 实现 TXT、EPUB 本地导入；随后完成文本型 PDF。
5. 接入通知、深链、账号注销、隐私授权和崩溃监控。
6. TestFlight、Android 内测、低端机性能测试。
7. 完成 APP 备案与商店材料后再生产发布。

不要把整个 Web 页面作为最终阅读器长期套壳。它可以用于很短的内部验证，但文件访问、长文性能、
系统字体、读屏、后台通知和商店审核体验都会受限。

## 应用商店材料

Apple 要求 App Store 元数据和 App 内都能访问隐私政策；使用相关系统 API 或第三方 SDK 时需正确
填写 Privacy Manifest：

- [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)
- [Apple Privacy Manifest](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)

Google Play 要求所有发布应用完成 Data safety 表；如果 App 内可创建账号，还必须同时提供 App 内
删除入口和网页删除申请链接：

- [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469)
- [Google Play 账号删除要求](https://support.google.com/googleplay/android-developer/answer/13327111)

中国大陆 Android 还需要逐个适配计划发布的国内应用商店；先选择 2–3 个主渠道，不要一开始同时
维护所有渠道包。所有商店共用同一隐私政策、版本号规则、签名管理和备案主体。

## 建议排期

- 第 1–2 周：翻译评测、Redis 缓存、内容影子运行、真实短信方案和生产数据库。
- 第 3–4 周：Web Beta 安全、隐私/删除流程、监控、压测、ICP备案材料。
- 第 5–8 周：Expo 移动端核心阅读、导入、生词、通知和端到端测试。
- 第 9–10 周：TestFlight/Android 内测、APP 备案、商店材料和整改。

上线时间最终取决于备案、应用商店审核、真实短信和内容人工抽检，不应只按代码完成时间承诺。
