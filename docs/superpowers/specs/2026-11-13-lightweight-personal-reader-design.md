# 苏打阅读轻量个人版：产品设计与路线图

> 日期：2026-11-13  
> 状态：第一阶段已实现并通过自动化与真实浏览器验收；后续阶段仍按依赖顺序推进。  
> 第一阶段实施计划：[生词学习闭环](../plans/2026-11-13-vocabulary-learning-loop.md)。

## 1. 产品目标

苏打阅读是一个**轻量、界面简约、面向个人使用的英语阅读器**。它对标的不是薄荷阅读完整的课程、社群和运营体系，而是其核心的分级阅读、辅助理解和持续学习体验。

产品的差异化是：

- 阅读正文优先，保持沉浸、克制，不用功能卡片、打卡、XP 或重动效打断阅读。
- 词义结合语境，生词能回到原文，复习能形成长期记忆闭环。
- 本地个人模式，无注册、无云同步要求，学习数据可导出和恢复。
- 优先复用缓存、预生成内容和确定性代码，AI 只处理语义判断、翻译、审核与生成等代码不擅长的环节。
- 默认零付费预算；低成本不等于声称模型永远免费，也不绕过供应商限额。

## 2. 范围与边界

### 要做

- 生词标记、分批复习、已掌握词库及完整备份。
- 高中、四级、六级、考研等内容轨道；CEFR 仍作为语言难度维度。
- 广泛但可验证的每日内容来源，以及低成本的质量筛选。
- 每天最多一篇按需生成并缓存的个性化 AI 文章。
- 统一的个人模型与密钥配置，按任务设置路由、额度和缓存。
- 阅读、复习和每日文章选择流程的持续体验优化。

### 不做

- 账号体系、社群、老师答疑、会员、积分和打卡奖励。
- 原生 App、云同步或新的云服务，除非用户另行明确要求。
- 为了“每日更新”而在无人使用时自动消耗生成额度。
- 把 AI 生成或改写文章伪装成考试真题。
- 无差别抓取全站、绕过反爬或许可限制。
- 为每个机械操作调用 AI，或为每次点击生成大段扩展讲解。

## 3. 十项需求与现有能力对照

| 需求 | 当前状态 | 处理方式 |
| --- | --- | --- |
| 1. 生词标记、复习、已掌握 | 已有点词后收藏、译义与原句存储、FSRS、隐藏答案、四档评分、忘记重排和撤销 | **修改为主**：增加连续标记模式、两阶段回忆、明确的批次界面和已掌握状态；保留 FSRS 与本地数据 |
| 2. 界面和阅读体验 | 已有简约阅读器、三种主题、排版设置和移动端目录 | **持续优化**：优先新功能涉及的阅读与复习路径，不做无目标的整体换皮 |
| 3. 四六级、考研真题 | 当前没有考试内容模型或真题库 | **新增内容线**：先小批量核验，再逐步扩大；科普和故事优先，保留题目、答案和出处 |
| 4. 高中每日文章 | 当前没有高中轨道；已有每日内容管道 | **扩展复用**：进入每日选题池，不一次性追求大量试卷 |
| 5. 广泛来源与优质筛选 | 已有来源策略、许可检查、语言/篇幅/新鲜度检查、去重和候选池 | **扩展复用**：增加来源与规则分级，AI 只处理 shortlisted 或边界候选 |
| 6. 每日 AI 文章 | 已有 CEFR 控制的内容生成、证据和付费护栏，但没有读者按需生成入口 | **新增入口并复用生成器**：兴趣、篇幅、CEFR、检索证据、每日缓存 |
| 7. 个人密钥与模型集合 | 已有本机模型路由、OpenAI 兼容端点、掩码显示和密钥本地保存 | **修改扩展**：按翻译、审核、生成等任务配置，不重复建设密钥库 |
| 8. 高集成但轻量、省 token | 已有代码化校验、缓存、请求合并和零预算默认 | **形成统一约束**：增加任务级预算、用量记录、上下文限制和持久缓存 |
| 9. 上下文翻译与缓存 | 已发送当前句和相邻上下文；已有浏览器记忆、后端缓存、同请求合并 | **保留并补强**：限制上下文、扩充常见用法、记录缓存命中率，不为相同文本重复调用 |
| 10. 浏览器音频 | 已有 Web Speech API 逐句听读和生词发音 | **保留**：不购买或生成云音频，只补兼容性与回归检查 |

## 4. 方案选择与取舍

### 方案 A：扩展现有本地架构（默认采用）

浏览器继续保存个人学习数据，SQLite 保存公共内容、审核结果和生成文章，模型提供方密钥继续保存在本机后端配置中，FastAPI 负责检索、翻译、审核和生成。优点是能复用 FSRS、翻译缓存、内容管道和模型路由，新增依赖少，最符合轻量低成本目标。

### 方案 B：重建为后端学习型应用

把所有个人数据迁入后端数据库，再建立完整课程和题库。数据查询能力更强，但会增加迁移、备份和运行复杂度，也会削弱当前“打开本地网页即可用”的优势，因此不采用。

### 方案 C：AI 优先自动完成所有环节

让模型自由搜索、审核、改写、出题和规划复习。开发初期看似省事，但 token 成本、事实错误、来源不明和结果不可复现都会扩大，因此不采用。

## 5. 生词与复习设计

### 5.1 阅读中的生词标记

- 默认点词行为保持不变：显示行间语境义，由读者主动收藏。
- 阅读工具栏增加“生词标记”模式。开启后，连续点击单词或短语会复用现有翻译与缓存，并在成功取得译义后保存。
- 已保存项目不重复创建；翻译失败时明确提示，不保存没有词义的空卡片。
- 生词仍保留文章、章节、原句、语境义、常见义、词性和音标。常见用法优先复用当前翻译结果；详细搭配或例句按需补充，不在每次点词时预生成。
- 已掌握项目仍可在后文安静标记；读者再次标为生词时可恢复学习，而不是制造重复记录。
- 第一阶段保留现有“文章＋词＋原句”的记录键，避免一词多语境迁移时丢失数据。是否按 lemma 合并展示，待实际使用后再决定。

### 5.2 两阶段主动回忆

1. 首屏显示单词和原句，不显示翻译，提供“认识 / 不认识”。
2. 点击“认识”后显示译义，再让读者判断：记错、困难、正确、轻松，分别映射 FSRS Again、Hard、Good、Easy。
3. 点击“不认识”后显示译义，并以 Again 进入本轮重学队列。
4. 保留撤销、键盘操作和“原文”返回；所有答案都先隐藏，不因切换界面意外泄露。
5. 复习页可手动“移入已掌握”；此操作可恢复，不在后台悄悄删除学习记录。

### 5.3 批次与时间安排

- 每批沿用个人设置中的 10 / 20 / 30 / 40 / 50 张，默认 20 张。
- 界面按批进行，批次完成后可继续下一批；首页显示全部到期数，而不只显示当前批数量。
- **底层仍按每张卡独立运行 FSRS。** 不让整批共用一个到期时间，因为同批词的记忆程度不同。
- FSRS 在本地计算，不消耗 token；“减少每个单词的独立计算”不会带来有意义的 AI 成本优化。
- 忘记的词在当前批重排，其他词按各自 FSRS 时间到期后重新进入待复习。

### 5.4 已掌握词库

- 使用同一生词集合中的 `learningState`，而不是维护两份可能失同步的数据。
- 状态为 `learning` 或 `mastered`；已掌握记录保留原句、译义和复习历史，但不进入到期队列。
- 默认只允许手动移入掌握，或系统达到条件后给出建议，由读者确认；不自动隐藏仍在使用的词。
- 已掌握页支持“恢复复习”，恢复后该词立即进入待复习批次。
- 自动掌握门槛不在第一版拍脑袋固定，待积累真实复习记录后再评估。

### 5.5 本地存储

- 小体量结构化学习数据继续使用浏览器 localStorage；导入书籍继续使用 IndexedDB；公共内容继续使用后端 SQLite。
- 不为生词单独引入新的数据库或服务。
- 备份升级为 schemaVersion 2，只接受当前版本；本阶段没有既有正式用户，不保留旧版本迁移分支。生词状态、FSRS 和掌握时间都必须进入备份。
- 密钥、模型凭据、会话和在线内容库仍不得进入个人备份。

## 6. 低成本 AI 与模型配置

### 6.1 任务分工

| 工作 | 默认实现 |
| --- | --- |
| 复习调度、去重、批次、进度、导入、字数和 CEFR 指标 | 确定性代码 |
| RSS/API 获取、许可检查、语言/篇幅检查、哈希和排序 | 确定性代码 |
| 上下文词义、整句翻译 | AI；优先预生成与缓存 |
| 候选内容语义审核 | 规则先筛选，AI 只审边界或入围候选 |
| 文章选题、证据摘要、受 CEFR 控制的写作 | AI；使用有界证据 |
| 发音 | 浏览器 Web Speech API |

### 6.2 统一模型中心

在现有 `/admin` 模型路由上扩展，不另建独立账号或密钥系统：

- 提供方配置：接口、模型、Key、启用状态和顺序。
- 任务路由：`translation`、`content_moderation`、`daily_article`；爬取本身不配置模型。
- 每个任务显示当前线路、缓存命中、估算/实际 token、成功与失败次数。
- 付费线路继续默认阻断；任务不得因为“审核”或“每日生成”而绕过既有付费总开关、每日预算和单次上限。
- 密钥只保存于后端本机配置，接口只返回掩码；不出现在前端包、日志、导出或更新日志中。
- 模型变更不迫使所有高质量既有缓存失效；缓存键至少包含任务、规范化输入、内容哈希、相关 CEFR 和提示词版本，并提供明确的清理入口。

### 6.3 上下文与缓存预算

以下作为实现时的起始默认值，需经翻译质量与费用实测调整：

- 单词/短语：当前句为必需上下文，前后最多各一句；长句和相邻句均截断，不发送整篇文章。
- 整句翻译：当前句为主，只有歧义时才依赖相邻句；预生成句译优先于云端请求。
- 内容审核：默认发送标题、短摘要、来源和必要风险片段，不把全部候选正文交给模型。
- 每日文章：代码先检索并筛选 3–5 个可靠来源，只把相关摘录交给模型；事实、数字、日期必须能回到证据。
- 浏览器翻译记忆和后端缓存继续合并相同请求；每日生成和审核结果持久化，避免重启后重复花费。
- 失败只短缓存并重试限次；不得用无限自动重试或付费 fallback 换取表面成功率。

## 7. 内容设计

### 7.1 考试轨道与 CEFR 分离

新增 `examTrack` 一类元数据，至少支持 `high_school`、`cet4`、`cet6`、`postgraduate`，普通文章为 `null`。CEFR 继续描述语言难度，不声称与任何考试官方等价。

考试内容还需保存：

- `contentOrigin`：`official_exam`、`licensed_exam`、`adapted`、`original`。
- 年份、批次、地区/卷别、英语一/二等可得信息。
- 原文、题目、选项、答案、解析和原文依据。
- 来源 URL、获取时间、许可/使用依据和校验状态。
- 若经过删节、改写或由其他文本转成阅读文章，必须标“改编”或“原创”，不得保留“真题”标签。

### 7.2 四六级与考研

- 优先科普、自然、技术、社会故事和叙事性较强的材料。
- 四六级先覆盖仔细阅读，再扩段落匹配、选词填空等题型。
- 考研先覆盖传统阅读与长难句，再区分英语一/二和其他题型。
- 先做小批量、可核验的样例集，验证正文、答案、解析和阅读器闭环，再扩大抓取；不把“爬取数量”作为第一验收指标。
- 公开网页可见不等于可任意复制再发布。无法确认使用依据的内容，只保留个人主动导入，或改为明确标注的原创模拟材料。

### 7.3 高中内容

- 复用每日来源池和小规模刷新，不一次性抓取海量学校试卷。
- 高考内容按可确认来源收录；普通模拟题以每日精选和兴趣/难度匹配为主。
- 题材可覆盖校园、成长、科普、文化和故事，题目以细节、推理、猜词和主旨为先。

### 7.4 每日普通内容的审核与精选

- 来源广泛必须同时满足来源登记、许可、去重和基本质量检查。
- 不用“正面/负面情绪”作为唯一质量标准。批评、争议或严肃议题可以引发思考；虚假健康建议、仇恨、煽动伤害、露骨内容、危险指导和低质标题党应被拒绝。
- AI 审核不能承诺绝对正确。低置信、证据不足或来源不可靠的候选不自动发布，也不为此恢复一个闲置的人工复核队列。
- 先由代码得到少量高分候选，再让 AI 做语义审核或排序；一次运行不全量调用模型。

## 8. 每日个性化 AI 文章

### 8.1 读者流程

1. 今日页置顶区域提供“今日 AI 文章”。
2. 读者选择兴趣方向、故事/科普等形式、大致篇幅和 CEFR；CEFR 默认采用读者手动选择的水平，水平测试结果只作参考。
3. 读者确认后，代码检索可靠资料并整理有界证据，AI 再生成自然、准确、接近正式阅读或考试风格的英文。
4. 中文资料可以翻译或改编为受 CEFR 控制的英文，但不得改变事实、数字、日期和因果。
5. 成功后生成导读、句译和必要词汇资产，当天置顶并复用同一文章。

### 8.2 每日一次与失败策略

- 按 Asia/Shanghai 自然日，每个本地读者每天最多保留一篇新生成文章。
- 只有当天首次使用且读者确认后才生成；应用未打开时不后台空跑。
- 当天重复打开、刷新或切换 CEFR 不重复生成；参数变更默认影响次日。
- 不在第一版提供无限“重新生成”。后续如确有需要，应单独确认并受预算限制。
- 生成失败或证据不足时使用已有每日内容，不展示伪造文章，也不连续自动重试烧钱。

## 9. 界面、交互与音频

- 界面优化贯穿各阶段，优先生词标记、复习、掌握词库、考试筛选和每日 AI 设置这些真实路径。
- 保持正文密度、行间译义和既有视觉基准，不增加功能卡片网格、渐变、气泡、重阴影或游戏化。
- 新交互需要清晰焦点、键盘操作、移动端触控面积和 `prefers-reduced-motion` 支持。
- 动效只用于表达状态变化，不为装饰拖慢点词、翻页和复习。
- 继续用浏览器语音完成单词和句子/全文朗读；不为“更标准”默认增加云 TTS 成本。
- 每个阶段在桌面和移动视口走通真实路径，而不只检查组件渲染。

## 10. 推荐实施顺序

> 下列顺序按依赖、个人价值和 token 风险排列，不是原需求的重要程度排名。

### 阶段 1：完成生词学习闭环

- [x] 生词标记模式、两阶段回忆、分批复习、已掌握与恢复。
- [x] schemaVersion 2 备份、严格验证和失败回滚。
- **先做原因：** 使用频率最高、完全本地、无 token 成本，也是后续所有考试与每日内容的学习出口。
- **验收：** 掌握词不进入到期队列，忘记会重排，恢复备份后状态一致，连续点词不会重复请求或重复建卡。

### 阶段 2：统一模型中心与成本护栏

- [ ] 按任务配置模型，保留本机密钥和零预算默认。
- [ ] 上下文上限、持久缓存、用量与缓存统计、失败限次。
- [ ] 复用并验证现有上下文词译和句译。
- **第二步原因：** 后续审核、每日更新和每日生成都依赖它；先统一能避免三条管道各自烧钱。
- **验收：** 未显式开启付费时付费调用为零；重复翻译不重复请求；日志和备份无完整密钥。

### 阶段 3：四六级与考研内容最小闭环

- [ ] 考试元数据、来源验证、正文/题目/解析模型。
- [ ] 小批量科普与故事类内容，先四六级/考研，再扩大数量。
- **第三步原因：** 能最快形成明确的个人备考价值，也能为高中与普通每日内容建立可靠的数据规范。
- **验收：** 每篇可追溯，答案和原文依据一致，改编不冒充真题，阅读后可复习对应生词。

### 阶段 4：每日内容扩展与高中轨道

- [ ] 更多合规来源、规则优先的审核和优质候选排序。
- [ ] 高中每日文章、小规模刷新和稳定降级。
- **第四步原因：** 复用阶段 2 的成本控制和阶段 3 的内容规范，避免先大量抓取再返工。
- **验收：** 来源失效不会破坏已有今日内容；重复率、主题覆盖和审核拒绝原因可观察。

### 阶段 5：每日个性化 AI 文章

- [ ] 兴趣/形式/篇幅/CEFR 设置、证据检索、受控生成、每日缓存。

- **验收：** 当天只生成一篇，刷新不重复收费，事实有证据，失败有正文可读的降级内容。

### 阶段 6：体验优化贯穿并回归

- [ ] 每阶段同步优化对应交互；最后统一做桌面、手机、键盘、减弱动效和听读回归。
- **不单独提前做大改版原因：** 先围绕真实学习路径优化，避免视觉完成后因新功能再次返工。

## 12. 默认决策与待验证事项

本次没有阻塞实施的问题，先采用以下保守默认值：

- 批次只组织界面，不共享 FSRS 时间。
- 已掌握仅由读者手动设置和恢复；第一版不自动移动，也不在缺少真实数据时固定建议门槛。
- 一词多语境的现有记录键暂不重建。
- 每日 AI 文章按需生成，不在无人使用时运行；当天参数变化不触发反复生成。
- 真题先正确、可追溯，再追求数量；版权/使用依据不明确时不批量收录。
- 内容审核不把“观点不同”或“情绪严肃”等同于低质量。
- 详细用法、例句和讲义按需生成，不给每次点词都附加长输出。

仍需在实施中通过真实样本验证的事项：

- 两阶段回忆是否比现有直接四评分更顺畅，键盘操作是否容易理解。
- 不同考试来源的稳定性、许可和答案可靠性。
- 各任务的最小上下文长度，以及免费线路的实际质量、限流和可用性。
- 已掌握的自动建议门槛是否有价值；没有足够数据前不固定阈值。
