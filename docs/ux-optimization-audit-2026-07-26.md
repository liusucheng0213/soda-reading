# 苏打阅读体验与生产化优化审计

> 审计日期：2026-07-26  
> 范围：桌面 Web、390×844 手机 Web、点词/句译、每日内容池、生产安全边界和原生 App 路线。  
> 访问目标：让中国大陆的英语学习者在不中断阅读节奏的前提下，看感兴趣、可信且难度合适的英文内容。

## 结论

本轮已经把项目从“能演示”推进到“适合继续做受控内测”的状态：

- 阅读器保持正文优先，桌面三栏和手机单栏均可用；日间暖白与夜间深色主题通过视觉复核。
- 点词翻译具备前端、后端内存和 Redis 三层缓存，相同并发请求只调用一次，并按免费线路的质量、
  近期成功率和延迟动态排序。
- 逐句翻译由句末标点直接触发，44×44 像素隐形触控区不再生成额外的青色圆点，也不会独占一行。
- 内容候选重新执行英文与证据完整性检查：当前 500 条可见候选中，186 条合格、304 条拒绝；
  合格池覆盖健康 29、科技 34、历史 8、商业 73、文化 23、自然 19。
- 付费模型默认关闭、每日预算为 0；生产模式下演示短信失败关闭，管理接口必须携带管理员 Token。

项目仍不适合直接公开注册。真实短信、持久化账号、生产数据库、隐私与注销流程、备案材料和连续
7 天内容影子审核仍是公开测试前的硬门槛。

## 翻译速度、准确率与成本

### 已实现

1. 浏览器会话缓存：当前会话重复点击不再请求后端。
2. 后端 TTL LRU：单进程内复用相同正文哈希、词、句子和上下文。
3. Redis 缓存：跨进程和重启复用；默认保存 30 天。
4. Single-flight：相同并发请求合并为一次供应商调用。
5. 失败短缓存：高负载时 8 秒内不重复冲击同一线路。
6. 动态路由：免费候选按质量 50%、近期成功率 30%、P95/平均延迟 20%重排，并对 429、超时和
   5xx 做短时熔断。
7. 费用护栏：付费线路只有在全局开启、预算大于 0、单次费用不超限且请求模式允许时才可能调用。

### 本机实测

在当前免费线路环境中，`bank`、`issue`、`charge` 均获得了真实上下文中文释义：

| 场景 | 结果 |
|---|---:|
| 免费模型首次上下文翻译 | 约 1.37–1.66 秒 |
| 同一会话内存命中 | 约 101 毫秒端到端 |
| 新网关实例 Redis 命中 | 约 2 毫秒，0 次云调用 |
| 当前可用免费首选 | ModelScope，5/5 成功，平均约 1.49 秒 |
| 付费调用 | 0；`PAID_PROVIDER_ENABLED=false` |

这是一轮小样本工程验收，不等同于正式 P50/P95 压测。生产前仍应使用 300 条人工校对集，并按小说、
新闻、论文术语、多义词、指代和专名分层统计质量。

### 性价比深化建议

- 公共推荐文章优先预热高频词句缓存，成本可在所有读者之间摊薄。
- 私有导入内容不上传整本，只发送当前句和必要相邻上下文；设置软额度和失败退避。
- 免费线路拥堵时不要并发竞速两个模型，否则请求量和潜在费用接近翻倍。
- 若未来启用按量模型，默认只提供用户主动选择的“精确翻译”，并设置每日预算、单次上限、余额告警
  和硬停止，不做静默自动扣费。
- 评估指标使用“每个完成阅读用户的翻译成本”，同时看缓存命中率、成功率和人工准确率，不能只比较
  每百万 Token 单价。

## 内容质量

### 已修复

- 标题与摘要分开执行英文检查，中文、印尼语、葡萄牙语等非英文候选不会因附带英文元数据而误通过。
- 证据摘要至少需要 18 个英文词且达到最小字符长度；不足以支持事实的候选不得成稿。
- 未获全文许可的来源只保存元数据和链接。
- 首页不再把备用内容伪装成当天发布内容。
- 自动发布仍保持关闭，避免未经人工观察就把新管道结果推送给用户。

### 继续深化

- 先连续运行 7 天影子采集，逐日抽检来源日期、版权、事实、CEFR 和完整逻辑。
- 给每篇文章增加“太难 / 合适 / 太简单 / 不感兴趣”，结合每 100 词查词次数调整后续难度。
- 健康、治疗、因果、争议研究与预印本保持人工审核。
- 当前主题分布中商业内容偏多、历史偏少；正式发布前应在选题阶段做主题配额，而不是发布后硬凑数量。
- 对 DOI、样本量、研究类型、局限性和数字结论建立可点击的证据回链。

## 可用性与无障碍

### 优点

- 阅读正文的视觉层级稳定，学习工具默认不打断内容。
- 单词和句子翻译可独立展开；加载、成功、基础翻译和失败状态可区分。
- `Esc`、再次点击和空白点击均可关闭学习浮层。
- 句末触控区域达到 44×44；键盘焦点有可见轮廓。
- 翻译结果使用 live region，读屏可感知状态更新。

### 剩余风险

- 英文单词作为行内按钮仍按自然排版宽度显示；这符合行内链接的实用形态，但还需要 VoiceOver、
  TalkBack 和大字体真实设备测试。
- 尚未完成完整 WCAG 审计、色彩对比自动扫描和读屏任务测试。
- 浏览器内登录状态仍偏演示性质，刷新、设备吊销和多端会话体验需要生产账号系统后再验证。
- 弱网、离线恢复和长篇 EPUB/PDF 的内存压力需要在低端 Android 真机上测试。

## 公网发布与原生 App

公开 Web Beta 前必须完成：

1. 真实短信、防刷、PostgreSQL 账号与可吊销会话。
2. 独立管理员登录、MFA、审计日志和密钥托管。
3. HTTPS、严格 CORS、限流、备份恢复、错误与额度告警。
4. 隐私政策、用户协议、第三方 SDK 清单、云翻译告知、数据导出与账号删除。
5. ICP/APP 备案与生成式 AI 场景的合规复核。

手机端推荐用 Expo/React Native 重建原生界面，并共享分词、句切分、推荐规则和 API 客户端；文件
保存使用应用沙盒与 SQLite，令牌使用系统安全存储。不要把现有网页长期套在 WebView 中作为正式
阅读器。

完整工程顺序、备案与商店材料见
[公网发布与手机 App 路线](./public-launch-mobile-roadmap.md)。

## 验证边界

- 本轮覆盖 1440×900 和 390×844，可视化检查了首页、阅读器、点词、句译和夜间模式。
- 浏览器控制台最终无 error。
- 自动化覆盖后端 API、翻译路由、内容过滤和前端组件/构建；尚未做多用户并发压测、真实短信、
  TestFlight、Android 内测和完整安全渗透测试。
- 免费模型策略与可用性会变化，生产路由必须继续以实时健康度为准，不能把“当前免费”理解为无限
  并发或 SLA。
